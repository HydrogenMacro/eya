# Test guide

Tests are plain Node scripts. Browser suites use Playwright from `client/node_modules`; protocol sources are bundled with esbuild so browser WebSocket and crypto APIs are available.

## Shared-host resource limits

- Run one browser suite at a time, including across subagents. Each browser can start several renderer and utility processes. Reuse one Playwright browser, close each test context before the next case, and keep disposable servers scoped to the suite.
- Run `bash scripts/run-browser-test.sh node tests/<suite>.cjs` on shared Linux hosts. It locks this checkout during the run and puts Chromium, the test process, and disposable servers in one user systemd scope. The defaults are 2 GiB memory pressure, 3 GiB hard memory limit, zero swap, and a 20-minute wall-clock timeout. Profiles and fixtures use a disposable directory under `eya-server/target` so a RAM-backed `/tmp` does not hold them. Adjust the scope only after checking host headroom. Fix excessive usage or split a matrix into sequential invocations if it hits the limit.
- Use `free -h` and inspect active browser tests before starting a run. Keep browser suites separate from heavyweight builds and streaming benchmarks. If per-user systemd is unavailable, use a dedicated test container or another memory-limited environment before setting `EYA_BROWSER_TEST_UNCAPPED=1`.
- Prefer one public site and client format for a smoke check. The full public matrix runs serially within one harness invocation. Test output and captures should go to a disposable directory. After any interruption, check that the corresponding test browser and server have stopped before retrying.

## Terminal network acceptance

`terminal-network-client.cjs` bundles source and tests bounded decoding, pacing, callbacks and heartbeat with deterministic socket/renderer stubs. `terminal-network-protocol.cjs` uses real Noise/PTYs for exact byte/offset compatibility and backpressure. `terminal-network-browser.cjs` uses real local HTML/SVG, CPU4x mobile emulation, hidden panels, non-echo input, suspension and generator opt-out. Build client/server before the real-server suites. Browser integration requires `nano`, `top` and ordinary Linux shell tools; WAN experiments require Python 3.

`terminal-network-wan.cjs` creates a private user/network namespace and runs actual TCP delay/rate/loss/reordering with `tc netem`; it refuses to modify the launching namespace. It needs `unshare`, `ip`, `tc`, namespace permissions and loopback-capable Chromium. Default: full 0/80/250/600 ms RTT × 32/64/256 kbit/s × raw/compressed matrix plus jitter/loss/reorder, severe 600 ms/32 kbit/s loss and competing-output cases. `EYA_WAN_QUICK=1` selects a subset; `EYA_WAN_REPORT=/tmp/report.json` saves machine-readable results. Reports measure renderer-observed echo via in-page mutation callbacks, not Playwright polling delays. These are controlled experiments, not device battery or production WAN measurements. `terminal-compression-benchmark.cjs` is a separate reproducible payload estimate.

`terminal-network-silent-outage.cjs` creates a private namespace, drops 100% of TCP packets, verifies that terminal/workspace watchdogs leave native closing sockets without waiting for close events, then restores the same shell/workspace and buffered input. It takes about 35 seconds plus startup.

`terminal-network-resources.cjs` measures production encoder/decoder CPU and actual Linux renderer/server `VmHWM` under a large Unicode terminal stream with CPU4x. It extracts the production Rust encoder function into a disposable offline release build; build the main server first so its pinned dependencies are cached. `EYA_RESOURCE_REPORT=/tmp/resources.json` saves source-hashed results. It measures codec CPU and process RSS separately from WAN latency.

## Continuity acceptance suites

Use `continuity-fixture.cjs` for disposable server roots, state directories, local HTML/generated SVG clients, and disabled browser storage. `workspace-manager.cjs`, `workspace-conflicts.cjs`, `workspace-viewers.cjs` and `workspace-layout.cjs` cover the workspace UI and feature restoration. `workspace-edge-cases.cjs` covers authentication retry bounds, uncertain save outcomes, storage failure and full-store recovery. `browser-workspace.cjs` and `browser-continuity-live.cjs` exercise real server Chromium; it must support its normal sandbox. Viewer tests generate a synthetic WebM with `ffmpeg`. Existing `browser-remote-panel.cjs` still expects advanced UI controls absent from the simplified current panel; see the continuity checkpoint rather than treating it as coverage for the new surface.

## File presentation and browser streaming

`browser-input-live.cjs` verifies drag and multi-click selection plus negotiated cursor hints through the real Chromium browser transport. `browser-proxy-panel.cjs` covers the separate proxy controls, zoom, safe restore URL and cancelable local HTML opening. `browser-proxy-workspace.cjs` checks the built client's panel launcher, sessionless workspace restoration and local HTML placement. Build client/server before the live and workspace suites; Chromium must support its normal sandbox.

`file-presentation.cjs` checks natural sorting, stable equal values, relative dates, units and subtitle matching/conversion. `file-presentation-live.cjs` uses a disposable server and ffmpeg to cover both browser tables, icons, text selection, saved units, image context downloads and streamed sidecar captions. `browser-context-actions.cjs` checks page menu override, consumed dismissal gestures, selection actions, menu icons and stream controls. `browser-stream-live.cjs` uses real server Chromium for capability selection, PNG/JPEG capture, retained tabs and inline/blob image downloads; set `EYA_BROWSER_EXECUTABLE` to a sandbox-capable Chromium. `browser-stream-compatibility.cjs` uses a raw old-protocol peer to check absent/unknown offers, baseline JPEG, explicit PNG selection and invalid settings. `file-icons-artifacts.cjs` checks embedded icons and encrypted file browsing in generated HTML, SVG and compressed artifacts, plus data-URL packaging. `generator-settings.cjs` also verifies secure UUID fallback in data origins. `generator.cjs` and `generator-compression.cjs` cover data-URL startup and configuration, with recoverable errors when Chromium blocks loopback WebSockets through its local-network policy; full-font URLs can exceed browser navigation limits. `browser-stream-benchmark.cjs` measures changing 4K dashboard captures over the real Noise transport with multiple quality/resolution presets; `EYA_STREAM_REPORT=/tmp/report.json` saves results. See `docs/browser-streaming.md` for methodology and limitations.

## Prerequisites

`keybinds.cjs` checks shortcut normalization, bounded overrides, disabling, unknown-ID preservation, exact modifiers, and conflicts. `keybinds-workspaces-ui.cjs` exercises shortcut categories, cross-category search, recording/reset/clear, conflict handling, actual image-viewer rebinding, workspace quick switching, manager icons, and narrow-screen bounds without a server. Workspace integration suites use `fixture.manage(page)` to open the manager through the dropdown.

`browser-keybinds.cjs` checks live shortcut changes in loaded sandboxed browser pages, disabled shortcuts, global action relay, synthetic-key rejection, and native getter/private-port protection against page prototype hooks.

`workspace-startup.cjs` verifies the default terminal, one-time startup across reconnect, minimized terminal execution and generated HTML/SVG starting-panel choices. `workspace-modal-v2.cjs` checks separate searchable scroll lists, icon controls, SVG drag-and-drop/keyboard moves and narrow-screen bounds. `panel-minimize.cjs` verifies mounted hidden views, lifecycle cleanup, restoration and both launcher lists. The shared fixture explicitly defaults `startupPanel` to `none` for tests that arrange their own panels; pass `null` to exercise the production default. Use `f.named(page)` before assertions that require disk persistence or new-client workspace reopening: anonymous records are memory-only.

Workspace continuity has self-contained suites: `NODE_PATH=client/node_modules node tests/workspace-continuity.cjs` and `NODE_PATH=client/node_modules node tests/workspace-protocol.cjs`. They launch a disposable server with their own state directory and fixtures; build client/server first. The UI suite uses local HTML and disables browser storage. The protocol suite covers PTY-free services and terminal/browser session ownership, takeover, end and expiry.

- Rebuild `client.html` with `node client/build.mjs` after client-source changes.
- Browser tests need `NODE_PATH=client/node_modules`; set `EYA_BROWSER_EXECUTABLE` when Playwright does not manage Chromium.
- End-to-end tests expect an isolated server on `127.0.0.1:18765` with the fixed test key documented in the root README.
- Tests that set `EYA_TEST_ROOT` mutate files. Point it only at a disposable directory containing the needed fixture (usually `seed.txt`).
- `EYA_BROWSER_NO_SANDBOX=1` is for containerized Chromium, not the normal default.

## Protocol bundles

Rebuild only the source under test:

```sh
NODE_PATH=client/node_modules client/node_modules/.bin/esbuild tests/noise-client.js --bundle --platform=browser --format=iife --outfile=tests/noise-client.bundle.cjs
NODE_PATH=client/node_modules client/node_modules/.bin/esbuild tests/file-protocol.js --bundle --platform=browser --format=iife --outfile=tests/file-protocol.bundle.cjs
NODE_PATH=client/node_modules client/node_modules/.bin/esbuild tests/system-protocol.js --bundle --platform=browser --format=iife --outfile=tests/system-protocol.bundle.cjs
```

The bundles are generated and ignored. Prefer one relevant suite over the entire browser matrix, then expand coverage when a change crosses protocol, workspace, mobile, or security boundaries.
