# Browser panel

The Browser panel provides an address bar, Back, Forward, Reload, local HTML viewing, and a tab menu. Open the tab menu to switch or close a tab, or create a tab with the button at its bottom. The toolbar wraps on narrow screens.

Internet pages run in headless Chromium on the Eya server. The standalone HTML or SVG client sends input and receives display frames over the Noise-authenticated browser WebSocket. Chromium is started on demand with a private temporary profile and validated SOCKS egress. Install a sandbox-capable Chromium or set `EYA_BROWSER_CHROMIUM` to its executable. To install Chrome for Testing's Stable headless shell, run `python3 scripts/install-chrome-headless-shell.py`; it downloads the matching host build from Google's official feed into `$XDG_CACHE_HOME/eya/chrome-for-testing` (or `~/.cache/eya/chrome-for-testing`). Eya discovers the installed shell there automatically. You can pass an install directory as the script's only argument. The shell runs headless by default, so Eya does not pass Chromium's `--headless=new` flag to it. Keep all archive resources beside its executable. One browser session is supported at a time; closing it removes the temporary profile. `EYA_BROWSER_GPU_MODE=auto` selects Vulkan when a GPU device is visible, `off` uses software rendering, and `vulkan` forces Vulkan. GPU availability and performance depend on the deployment host.

The browser endpoint is part of the main Eya server; there is no separate browser service to start. The server process must run as a non-root user on a host that supports Chromium's sandbox, with Chromium and its system dependencies installed. For the Chrome for Testing Headless Shell on Ubuntu 24.04, install its runtime dependencies with `sudo apt-get install ca-certificates fonts-liberation libasound2t64 libatk-bridge2.0-0t64 libatk1.0-0t64 libatspi2.0-0t64 libcairo2 libcups2t64 libcurl4t64 libdbus-1-3 libexpat1 libgbm1 libglib2.0-0 libgtk-3-0t64 libnspr4 libnss3 libpango-1.0-0 libudev1 libvulkan1 libx11-6 libxcb1 libxcomposite1 libxdamage1 libxext6 libxfixes3 libxkbcommon0 libxrandr2`. On other distributions, install the corresponding packages listed in the shell archive's `deb.deps` or `rpm.deps`. You can override automatic discovery with `EYA_BROWSER_CHROMIUM`. The current Docker image does not include Chromium and runs Eya as root, so it does not support the server browser without additional deployment work. After updating Eya, rebuild the client and server and restart the server to use the updated embedded client and backend.

The Local HTML action opens an HTML file under Eya's file root. Relative links to other HTML files and relative presentation assets are read through the authenticated file transport. Scripts are disabled; dynamic applications and script-based search do not work in this viewer.

Bookmarks, browsing history, DevTools, extension management, and proxy-mode controls are not exposed in the simplified panel. Back and Forward use the active Chromium tab's navigation history. Fast client-side proxy rendering remains incomplete and is not exposed; it cannot guarantee that every page request stays on the WebSocket.

Server browser resource usage depends on the page. Optional hard limits require a writable delegated cgroup v2 subtree in `EYA_BROWSER_CGROUP_ROOT`; `EYA_BROWSER_CGROUP_MEMORY_MB`, `EYA_BROWSER_CGROUP_CPU_PERCENT`, and `EYA_BROWSER_CGROUP_PIDS` tune the limits. Without a delegated subtree, Chromium's renderer and JavaScript heap settings are best-effort limits, not a hard aggregate cap. A systemd service can alternatively set aggregate `MemoryHigh=`, `MemoryMax=`, `CPUQuota=`, and `TasksMax=` for Eya and its children.

The browser WebSocket is authenticated with the Eya key. Destination validation, public-address checks, DNS pinning, and redirected-request validation apply on server egress. The client-side viewer should not be treated as a general sandbox for executing local HTML scripts.
