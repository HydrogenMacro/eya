# Task Manager

Open **+ → Task Manager**. **Processes** combines live CPU, memory, and network charts with a searchable, sortable process table. **Performance** expands the charts and adds per-logical-CPU meters and per-interface network rates.

The server samples aggregate CPU, memory, swap and network counters every 500 ms and retains five minutes in bounded memory (at most 601 points). Opening or returning to Task Manager fills its graphs from that history, including time spent in another panel or browser tab. History begins at server startup and is never written to disk. The sampler reads three aggregate `/proc` files; it does not scan processes.

Graphs can show one, two, or five minutes. Area/line style, graph visibility, update interval, row density, process-tree layout, and optional columns are available in **Task Manager options** and the client settings. Settings initialize from the client defaults and are saved with workspace preferences. Process polling defaults to 500 ms, with 250 ms through 10 second choices. Inactive panels stop process polling; returning to the panel fetches current data and missing history. Pause freezes the panel; Refresh requests one sample.

History uses an optional `system.stats` request member `history:{v:1,after}`. `after` is the last received server timestamp in milliseconds. A supporting server selects version 1 with `history:{v:1,now,samples}`; samples contain `time,cpu,memory,swap,rx,tx`. CPU is a percentage, memory/swap are bytes, and network values are bytes/second. `now` aligns server timestamps to the client clock. The request is read-only and uses the existing authenticated machine transport and response chunking. Missing history means baseline live sampling; absent or unknown history versions receive the unchanged baseline response. Unknown fields are ignored.

Click a column heading to sort and click again to reverse direction. Name/PID/command/UID search combines with state and user filters. Tree layout retains parent-child relationships inside the filtered set. Use each parent’s chevron or Left/Right keys to collapse or expand its descendants. Collapsed state survives refreshes and is tied to the process start identity, so PID reuse does not affect a different process. Optional columns include user, state, threads, virtual memory, and nice value; PID/CPU/resident memory remain visible. Export downloads the current filtered/sorted table as CSV.

Double-click a process or choose **Details** for its command, working directory, executable, memory, thread count, priority, and I/O counters. **Terminal here** opens a terminal in its working directory; **Open executable** uses the existing file viewer. Access failures remain visible without erasing previous process data. No environment variables are read.

End task, Force kill, Pause, and Resume use the same authenticated machine API as the existing process controls. Delete/Backspace requests termination for the focused row. Destructive controls require confirmation and include the process start identity so a reused PID is not targeted.

CPU utilization is calculated from deltas in the first eight Linux CPU counters, excluding guest counters already included in user/nice. Per-process CPU is normalized to one logical CPU and may exceed 100%. The first sample displays Sampling. PID identity changes reset that process's CPU delta. Memory charts show resident system usage and swap; network charts show bytes per second computed from cumulative counters and elapsed client time. Counter resets produce zero rates. Permission-restricted `/proc` fields can be unavailable.

`client/task-manager.js` exports `createTaskManager({request, openFile, openTerminal, refreshInterval, preferences, onSettingsChange})`. The returned panel exposes lifecycle hooks and `api.refresh()`, `api.focusSearch()`, `api.setView(view)`, `api.getState()`, `api.openSettings()`, `api.getSettings()`, and `api.updateSettings(settings)`. `system.process` reads bounded command/status/I/O fields and checks process identity before and after the snapshot.

Run `tests/task-manager.cjs` for deterministic CPU/PID-reuse calculations, immediate history and inactive-gap recovery, faster polling, collapsible trees, settings callbacks, inspector integration, signal identity, and mobile bounds. `tests/task-manager-live.cjs` checks history through the real authenticated server and panel lifecycle. Real `/proc` snapshots and signaling an owned disposable process remain covered by the server's tests.
