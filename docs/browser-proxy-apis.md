# Proxy browser API inventory

Assessment: 2026-11-16. This inventory describes Eya's implementation, not conformance to the Web platform. Source: `client/browser-panel.js`, `client/browser-proxy-apis.js`, `client/browser-transport.js`, `client/html-viewer.js`, and `eya-server/src/browser.rs`. Server Chromium remains the recommended choice for applications that need their actual web origin or native browser APIs.

## Origin and sandbox contract

Internet documents still run as `srcdoc` in an iframe with exactly `sandbox="allow-scripts"`. No `allow-same-origin`, native form, popup, ancestor-navigation or device permission has been added. The page cannot read the outer Eya document, Noise credentials or transport object. Its private MessagePort offers individual bounded proxy operations, not the parent application API. CSP retains `connect-src 'none'`, `frame-src 'none'`, `object-src 'none'` and `form-action 'none'`; presentation resources are materialized into blob/data URLs.

The frame's actual origin is opaque. Its actual Location, `event.origin`, secure-context status, browser storage identity and `WindowProxy` relationships are not the upstream site's. The virtual URL, cookies and History API do not change that. A writable JavaScript shim is not a network enforcement mechanism: scripted frame self-navigation can still escape interception. The permanent client-network warning remains necessary.

Local HTML uses a separate script-free loader and authenticated file callbacks. None of the internet runtime, virtual cookies or API gates below enable scripts in local files.

## Supported and restricted behavior

| Area | What works | Boundaries and explicit failures |
| --- | --- | --- |
| HTML/CSS/DOM | Client-native text, layout, selection, local hover, rewritten presentation resources | Resource neutralization and rewriting are incomplete browser emulation. Nested frames/objects are removed or blocked; no origin-correct embedded application environment. |
| Classic JavaScript | Inline and materialized classic scripts; some Location assignments/calls rewritten through the navigation bridge | Rewriting is not a complete interpreter. Dynamically generated/aliased navigation is not guaranteed to relay. Execution ordering and parser-dependent scripts need compatibility testing. |
| Page modules | Bounded same-origin static and on-demand page graphs, computed dynamic imports, import.meta.url and native import-map-backed cyclic evaluation | 64 graphs / 8 MiB source per document; graph URLs live until navigation. General upstream import maps, bare specifiers, import attributes and unsupported syntax remain unavailable; page compatibility views do not grant native upstream origin privileges. |
| Dedicated workers | Same-origin classic workers with preloaded static `importScripts`; bounded module worker graphs; bridged fetch/asynchronous XHR; termination cancels source/fetch work | Four workers per tab, two concurrent fetches per worker and a 4 MiB response bound; graph limits remain in the loader. Literal dynamic module imports and import.meta.url are supported within the bounded preloaded worker graph; computed worker imports and cycles remain unsupported. No arbitrary worker origin or browser-native origin identity. |
| Shared/service workers | No upstream-origin worker registration or shared worker broker | Present SharedWorker constructors throw `NotSupportedError`. ServiceWorker access rejects with `SecurityError`; existing native opaque-origin getter errors retain their original details. No fake registration/ready success. |
| URL/history | Links and supported forms relay. Interactive pages have virtual same-origin pushState/replaceState, popstate and bounded per-document history. | Clients without the Navigation API use reader mode for styled pages, links, fragments and GET forms. Interactive `window.open` can request an Eya tab and returns null. Popups requiring an opener handle, named window identity or OAuth handshake need the Browser panel. |
| Fetch | HTTP(S) bridge, bounded body assembly, AbortSignal cancellation, credited response streams, virtual cookies and CORS checks | Not the native Fetch network stack. Request bodies are buffered up to 4 MiB, so this is not streaming upload. Redirect, response URL, opaque response and error semantics are reconstructed. Unsupported or disconnected operations reject rather than switch to direct fetch. |
| XHR | Asynchronous bridge, ready-state/header access, several response types, cancellation and timeout events | Synchronous requests throw `NotSupportedError`. Response bodies are buffered before completion. Upload progress is incomplete. Page and worker `overrideMimeType` calls throw `NotSupportedError` rather than accept an ineffective override; worker calls after send retain `InvalidStateError`. |
| EventSource | Incremental bounded event parsing, ID and retry handling, cancellation | Error/redirect/CORS behavior is an approximation. A terminal unsupported status/type closes the stream. Reconnect may issue a fresh GET according to page-level EventSource behavior; it cannot resume arbitrary application state. |
| WebSocket | Authenticated upstream socket bridge; protocols, text/binary messages, close/error, credited input | Eight upstream sockets per server proxy session, 1 MiB message/queued-send limits. No transport-resumption guarantee, extensions negotiation or native client socket identity. Closed sockets are not silently reopened/replayed. |
| sendBeacon | Bounded best-effort POST through the bridge | A true return means accepted for asynchronous attempt, not delivered. There is no background service surviving client close. |
| Cookies/CORS | Virtual per-panel cookie jar with origin/path/expiry/secure checks and separate HttpOnly visibility; bounded preflights/header filtering | Not the browser's cookie store, partitioned-cookie engine, native SameSite computation or complete CORS implementation. Redirect/auth/cross-site behavior needs per-site evidence. No cookie persistence in workspace descriptors. |
| localStorage/sessionStorage | Quota-bounded virtual maps and emulated storage events | Values live in client runtime memory and do not gain upstream native storage identity. Saved tab URLs do not serialize this state. Partitioning/clearing policy is described in the proxy roadmap. |
| IndexedDB/Cache Storage | No upstream-origin persistent store | Access throws `SecurityError`, preserving an existing native getter SecurityError where present. No success-shaped empty database/cache substitute is installed. |
| Forms and file inputs | GET/POST form relay; client-browser file inputs can be used where the browser permits the sandboxed picker; downloads use existing proxy materialization | Native form submissions stay disabled. POST/upload bodies are bounded and never restored/replayed by workspace loading. This is not Chromium's combined Eya server/device chooser or File System Access bridge. |
| Filesystem handles | No origin-scoped persistent handles | Present showOpenFilePicker/showSaveFilePicker/showDirectoryPicker reject with `NotSupportedError`. Use a normal page file input/download, Local HTML, or Browser as appropriate. |
| Clipboard/share | No page-initiated device clipboard or share bridge | Present methods reject with `NotSupportedError`; canShare returns false. Client selection/copy and outer Eya UI retain their separate behavior. Chromium's approval bridge is not invoked by proxy pages. |
| Dialogs/print | No proxy dialog/PDF bridge | alert/confirm/prompt/print throw `NotSupportedError` rather than silently using an ignored sandbox dialog or returning apparent confirmation. HTML/CSS in-page dialogs remain ordinary DOM. |
| Location/notifications | No client location or OS notification grant | Geolocation invokes its error callback with permission-denied code 1; watchPosition creates no watch and returns 0. Notification permission/requestPermission report denied; construction throws `NotSupportedError`. No OS prompt is opened. |
| Credentials/payment/authentication | Ordinary server HTTP requests and virtual cookies only | Present Credentials methods/PaymentRequest reject with `NotSupportedError`. No passkey/WebAuthn, FedCM, credential store, client certificates or payment sheet is bridged. HTTP auth challenges do not have a dedicated prompt. OAuth flows requiring real origins/opener identity cannot be represented reliably. |
| Camera/microphone/screen/devices | No native device/media bridge | Present mediaDevices capture/enumeration, USB/Bluetooth/serial/HID requests, MIDI and XR session calls reject. They cannot prompt for or accidentally use this device through these entry points. RTCPeerConnection remains disabled by the existing runtime. |
| Fullscreen/pointer lock | Outer panel UI remains separate | Present page fullscreen methods reject; pointer-lock calls throw `NotSupportedError`. No implied panel/device state or lock grant. |
| Permissions | No unified native upstream/client grant registry | Known unsupported permission queries reject with `NotSupportedError`; malformed and unknown descriptors retain native validation. An unrelated native granted result is never presented as a working bridge for the gated permissions. |
| Cross-document messaging | Native sandboxed frame messaging and the private Eya broker | No synthesized upstream origin/source identity. Third-party frames and popup authentication handshakes are unsupported; adding allow-same-origin is not a compatibility fix. |

The gates only replace APIs already exposed by the client browser. Missing APIs remain absent for feature detection. Methods that cannot be replaced retain their native sandbox restrictions. The gates are deliberate compatibility/error handling, not a complete inventory of future browser APIs or proof of confinement against hostile scripts. Pages can modify their own JavaScript environment; the iframe boundary and outer host validation remain the security boundary.

## Diagnostics and next work

Each gated API's first use emits one short warning to Proxy browser DevTools Console: “API is unavailable in Proxy browser. Open in Browser.” Reporting is capped at 48 distinct API labels per document and contains no arguments, URLs, form fields, credentials, clipboard text or device data. The original call still fails using its promised, synchronous, permission-result or callback shape; swallowing a diagnostic does not turn rejection into success.

The deterministic API regression (`NODE_PATH=client/node_modules node tests/browser-proxy-apis.cjs`) exercises a real opaque iframe, denied asynchronous/synchronous APIs, callbacks, deduplicated diagnostics, retained native errors, absence-preserving feature detection and denied access to its parent document. It uses sentinel APIs to prove blocked calls do not reach the underlying methods. The broader compatibility corpus records observable site behavior separately.

Remaining work is evidence-driven: test the inventory against representative applications; make unsupported resource/module errors similarly actionable; decide which supported API differences merit targeted fixes; establish a trusted egress architecture before treating arbitrary internet applications as confined. Persistent origin storage, complex authentication, cross-origin embeds and device bridges each need their own permission/isolation design. They are not enabled by the P1 diagnostic implementation.
