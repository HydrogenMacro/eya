# Workspaces and retained sessions

Connect authenticates an independent workspace/file/machine connection, then opens the generated client's configured starting panel. The default is a Terminal; the generator can choose Files, Browser, Task Manager, Docker, the New panel launcher, or no initial panel. That choice runs once for a fresh client connection, not on reconnect or when selecting a saved workspace. All terminals are independent; none is a primary or hidden connection anchor.

Every new page starts in a separate **Anonymous workspace**. It is temporary server memory, never a durable workspace file or backup. The running page keeps its server-issued client ID only in memory and uses it to reconnect to the same temporary workspace. A new page gets a new Anonymous workspace. The manager lists named workspaces and this client's anonymous workspace; other clients' temporary workspaces are not presented as saved projects. Choose **Save workspace** and give it a name to retain its current tabs, live-session references, minimized tabs, preferences and layout on disk. Eya uses no browser-local continuity storage and never silently selects a server-wide last workspace.

The header workspace button opens a dropdown for quick switching. **Manage workspaces** opens independently searchable, scrollable **Workspaces** and **Open tabs** lists. Icon actions support Open, New workspace, Rename, Save workspace, Save as, and Delete. Opening a workspace closes the modal automatically. Save as copies recipes and layout without sharing terminal/browser processes; those copied process tabs require an explicit replacement session. Saved tabs previews a workspace without opening it. The current Open tabs list includes minimized tabs and unsaved editors.

Drag a current tab onto another workspace in the manager to move it. On touch screens, drag its move handle; with a keyboard, activate the handle, then focus a destination workspace and press Enter. Escape cancels. The move updates both manifests and revisions in one server commit, detaches its view and leaves its process alive. The destination is opened explicitly. Dirty editor buffers and queued terminal input require a discard warning before moving; neither is stored with the recipe.

Minimize hides a tab while keeping its current view and runtime alive in the background. It disappears from the tab strip and mobile panel selector but stays in its workspace. **New panel** contains two independently searchable, scrollable lists: panel types to create and minimized tabs to reopen. Reopening preserves the existing editor buffer, terminal session or browser process. Closing a tab still closes its view and ends its terminal/browser session. Minimized state is retained in named workspaces.

Opening another workspace detaches the current interactive sessions and closes its client views, including minimized views. Deleting a workspace confirms ending its assigned live sessions. A failed end request is reported; detached processes remain subject to their expiry. Temporary workspace expiry also leaves any remaining runtimes subject to their own detached-session expiry. Unsaved editor buffers are not durable.

## Retained state

Named workspaces save ordered tab recipes, minimized flags, group membership, active tabs, recursive split orientation/ratios, file-browser cwd, file viewer path/type/version, video time and intended playback state, and workspace display preferences. Anonymous workspaces keep the same manifest only in server memory. Sash ratios are unitless fractions. A temporary mobile presentation does not change those ratios.

Pane minimum dimensions belong to the workbench: panel types/definitions may declare `minWidth` and `minHeight`, with defaults of 240 × 160 CSS pixels. Nested split constraints include both children and their sash. Sash input is clamped to usable sizes; when the viewport cannot fit all minimums, a single group is shown and the panel switcher reaches the others. Saved ratios remain unchanged during viewport resizing.

Client instances retain current DOM, editor buffers, CAD models and transient state in memory across brief outages. Fresh instances recreate views. CAD camera, measurements and selections; editor drafts; focus; scroll; chart history; menus; and panel search/filter history are transient. Browser-side settings use page memory; workspace appearance settings are saved on the server. Remote Chromium retains its process and temporary profile across disconnects, with independent authentication and attachment ownership.

Dirty buffers and unsynced workspace edits are lost if their page ends. Anonymous workspaces are not saved projects. The header distinguishes Temporary · not saved, Saved, pending/offline changes, unsaved storage errors, and conflicts. Page-close prompts are best effort. Closing or replacing a dirty view asks before discarding it. Missing files, changed file versions, unknown panel types and unavailable processes remain as recoverable entries. A changed file requires explicit reload; a replacement terminal/browser requires explicit start.

## Persistence and bounds

`EYA_STATE_DIR` selects a server-controlled directory. The default is `$XDG_STATE_HOME/eya`, or `$HOME/.local/state/eya`. Set it explicitly for services without these variables. Each server must use its own directory; an exclusive process lock prevents two servers from modifying the same store. Mount a persistent volume at this directory in containers. It is separate from `EYA_CWD` and the host filesystem namespace used for file operations.

Schema 1 stores only named workspaces in `workspaces.json`, with restrictive directory/file permissions (0700/0600), a backup, and atomic replacement followed by directory sync. Older schema-1 anonymous records are ignored when loading; named records remain compatible. A successful response acknowledges durable commit. A failed commit leaves the client visibly unsaved. An unsupported schema fails startup instead of overwriting data. Damaged JSON is quarantined and a valid backup is loaded when available; invalid records in an otherwise readable store are isolated and their source preserved. Warnings are returned after authentication.

Limits: 64 named workspaces and separately 64 anonymous workspaces, 128 tabs per workspace including minimized tabs, 48 KiB serialized per workspace, 8 KiB per panel configuration, 4 MiB durable metadata, 256 layout nodes, depth 16, bounded names/paths/IDs. Anonymous workspaces have a ten-minute renewable in-memory lease. The connection renews its original page workspace every minute, and the client separately renews an explicitly selected workspace. Deleting/replacing its anonymous workspace retains the same page identity. Expired records are pruned when the store is accessed. Anonymous edits, renewal and expiry do not write to disk; a full or unwritable durable store does not block temporary work. IDs identify records; all access requires existing shared-key Noise authentication. There are no accounts or user ownership features.

PTYs and Chromium processes are in memory. Server restart preserves named workspace metadata and marks old session references unavailable. Anonymous records disappear. A surviving page keeps its editor buffers/views and rebinds its local recipes to a new anonymous record instead of discarding its views or opening another default terminal. Detached Browser runtimes use `EYA_SESSION_TTL_SECONDS` (600 seconds by default); terminals have no detached expiry; eight terminal sessions and two concurrent Chromium processes are allowed. At most four browser session actors and 32 workspace connections exist. A retained but disconnected process still consumes its slot. Animated Chromium pages are checked for expiry independently of CDP activity. A full or unwritable durable metadata store still permits authenticated temporary work and management; explicit saves report their storage failure visibly. Full terminal transcripts are not saved: a new client gets the live PTY and available bounded replay, without a guarantee of previously acknowledged scrollback.

## Concurrent clients and recovery

Clients may explicitly open the same workspace. Updates require its current revision. Stale writes are rejected and the client preserves local state, offering Reload saved workspace or Keep as new workspace. Copies cannot share live session ownership. Only one client may attach an interactive session. Focusing a terminal automatically takes over its retained session; a taken-over attachment waits for a new focus action rather than reclaiming it immediately. Browser sessions show In use and require the Take over button. Takeover detaches/fences the former transport. A reconnect never sends queued terminal input to a replacement shell.

File, directory and system requests have deadlines; disconnect rejects pending requests and pauses polling. Readiness means Noise authentication and protocol negotiation completed. Three opened connections that fail negotiation stop automatic workspace retries and ask for Connect after correcting the password/server version; ordinary unreachable-server failures retain backoff. Late responses and panel creation results are fenced by connection/workspace generation. Mutations are not replayed: a lost response may mean a save, rename, delete or machine action completed, so refresh before retrying. Editor uploads check their original file version at replacement, serialized against other Eya upload commits. External host writers do not participate in that lock; the check is not a filesystem-wide compare-and-swap.

Video retries only bounded, version-checked range reads and can recover its decoder after authenticated readiness. Playback time is sampled at a bounded rate; restoring intended playback still follows the browser's autoplay rules. Physical iOS suspension and media policies require device verification separately from browser emulation.

## Protocol

After the existing terminal Noise handshake, a control client confirms with `eya-workspace-v1:{"client":null}`. The server returns type 7 JSON containing `state`, an ephemeral `client` ID, the client's starting `workspace`, and any storage warning. Reconnect supplies that same page ID. Requests use existing type 4 JSON framing and type 4–6 response/chunk framing, without any terminal opcodes.

Operations: `workspace.start`, `workspace.renew`, `workspace.list`, `workspace.create`, `workspace.load`, `workspace.update`, `workspace.rename`, `workspace.copy`, `workspace.delete`, `workspace.move_tab`; `session.list` and `session.end`. Updates include `workspace`, `revision`, `tabs`, `layout`, and optional `preferences`. Tab descriptors may include `minimized:true`; minimized tabs remain in the manifest and are excluded from the layout tree. Every visible tab must occur exactly once in that tree, and every minimized tab zero times. Move includes source/destination revisions and a tab ID. A revision conflict returns `conflict:true` and the current records. Files and machine operations keep their existing request names.

Terminal v4 confirmation additionally accepts `client`, `fresh` and `takeover`. A fresh attach adopts the committed input acknowledgment and the server's `nextInput` submitted cursor, so new keystrokes follow bytes still waiting in the PTY writer. It never imports or replays the prior page's queue. The browser endpoint supports `eya-browser-session-v1:` followed by JSON with `session`, `client`, `create`, `takeover`; its initial JSON reply reports state, session ID, resumed flag, target tab IDs/URLs and active target. The legacy terminal and browser handshakes remain supported.

## Checks

`tests/workspace-continuity.cjs` runs local HTML clients with browser storage disabled against a disposable server. `tests/workspace-protocol.cjs` checks authenticated services with no PTY and explicit terminal/browser attachment ownership, takeover, end, detach/resume, startup errors and expiry. All integration suites below launch disposable servers with temporary `EYA_STATE_DIR` directories; build the client/server first. Rust workspace tests cover durable restart, leases, revisions, validation, copies, atomic tab moves, failed writes, corruption, permissions and store ownership.

Normal SIGTERM/Ctrl+C shutdown requests session cleanup and waits for its bounded deadline. Chromium also receives a Linux parent-death signal if the server exits abruptly. Hard crashes can leave temporary profile files; an old runtime is never reattached after server restart. Real-Chromium tests verify explicit-end, expiry and graceful-restart PID/profile cleanup. The [implementation checkpoint](workspace-continuity-plan.md#implementation-checkpoint) records acceptance evidence and device-validation limits.

Session creation is a one-shot mutation: once a terminal create confirmation is sent, reconnection uses the existing ID and `create:false`, even if the reply was lost. The browser records its proposed session ID before connecting and similarly reconciles an uncertain creation by ID. An idempotent end request places a bounded 30-second cancellation marker (up to 1024), preventing a late authenticated create from reviving a closed tab. These markers are process memory and contain no input or key material.

Terminal runtimes have no detached expiry, including when no client is open. The separate anonymous metadata lease and Browser runtime TTL remain unchanged. Save a workspace to keep its terminal references available to new pages; metadata expiry does not kill its terminals. Detached terminals count toward the eight-terminal limit until explicitly ended or the server stops. Unreferenced sessions are available through authenticated `session.list` / `session.end`.
